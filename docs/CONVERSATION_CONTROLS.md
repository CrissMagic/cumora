# 会话暂停与跨工作区通知

本功能对应本 fork 的 Windows 本机智能体、PC 客户端和 Android 客户端。
它需要服务端、客户端及本机 daemon 配套升级；已有公开安装包不因此自动包含本地源码修改。

## 暂停与恢复

聊天页的“暂停智能体”针对当前会话的所有本机智能体。暂停状态保存在 PostgreSQL，
刷新页面、重启服务或收到新消息都不会恢复；只有用户点击“恢复智能体”才会恢复。
暂停期间人类仍可聊天，消息保留未读，恢复后继续处理。

界面区分两种状态：

- **已暂停新任务 · 等待本机确认停止**：服务端已经禁止该会话的唤醒、收件箱消费和智能体回复入库，
  但尚未收到所有当前智能体的停止确认。本机离线、旧 daemon 或网络中断时会停留在此状态。
- **已暂停**：所有当前智能体的 daemon 已确认不再执行该会话的当前任务。
  确认绑定智能体的本次电脑分配和暂停版本，旧电脑、旧请求不能确认新的停止操作。

取消包括本机初筛、等待模型并发名额的任务、正在运行的模型，以及关联当前会话的排队唤醒。
同一模型执行可能同时处理多个群：暂停其中一个群会中断这次合并执行，再将其余群的未读消息重新处理。
其余群不会变成暂停状态，但可能短暂中断。独立的看板 agenda 工作不随聊天暂停。

服务端对回复写入与暂停使用同一会话行锁；快速“暂停→恢复”后，旧版本执行的回复仍被拒绝。
本机 IPC 请求固定使用发起时的执行版本，并随该执行取消；每轮收尾等待 broker 停止，
下一轮启动前清除旧请求文件，避免排队请求借用恢复后的身份继续执行。
若旧协议文件因占用或权限问题无法清除，则阻止下一轮启动，不忽略错误后继续处理旧请求。
其他群的迟到消息若属于已暂停或已换版本的会话，会被拒绝注入，不取消当前群的执行。
已经提交的消息和已经完成的本地文件、命令副作用会保留，暂停不执行回滚。
当前不提供 managed/cloud 引擎的执行取消入口，服务端也会明确拒绝这类暂停请求。

本机控制 SSE 用于及时通知，执行期间每 2 秒读取持久状态作为回退；空闲时降低至约 15 秒。
网络故障时无法保证模型立即结束，此时界面不会显示停止已确认。

## 跨工作区通知

全局在线状态继续用于成员列表。推送是否需要发送则根据“用户正在查看哪个工作区”判断：

- 在 A 工作区前台时，B 工作区的消息仍可产生应用内提醒及系统推送。
- 当前工作区的前台消息保持原有提醒行为，不额外重复弹窗。
- 点击跨工作区提醒会先切换工作区，再加载并检查会话成员资格，随后进入对应群聊。
- 静音、消息作者本人、已离开的成员和会话旁观者不接收提醒。

查看状态使用 Redis 中按用户、工作区、连接区分的 75 秒租约。客户端收到认证完成的 `hello`
后首次上报、每 20 秒续约；重连后再次等待 `hello` 并立即上报当前状态。
切后台或断连时删除本连接的租约。多个标签页、设备和服务副本不会互相覆盖。
Redis 不可用时允许系统推送继续发送，以免全局在线状态造成永久静默。
应用内提醒仍需 WebSocket 通路可用；手机锁屏系统推送还需要部署自己的 FCM/APNs 凭据。

本轮没有增加跨工作区未读数的持久聚合。各工作区原有会话未读数在切入加载后继续显示。

## 升级顺序与验证

沿用 [云部署说明](./CLOUD_DEPLOYMENT.md) 的备份、构建及迁移流程。
本轮新增不可变迁移 `0016_conversation_agent_control`，不修改历史迁移。
该版本要求 schema 16；应协调服务端重启，不能让要求 schema 15 的旧服务与新服务混跑。

1. 备份数据库，更新服务端源码及镜像，执行迁移并启动新服务。
2. 更新本机 daemon，重启其后台服务。更新前确认有无需要先完成的本机任务。
3. 构建并安装配套 PC/Android 客户端，确认聊天页出现暂停入口。
4. 在测试群发起任务，暂停并等待确认；确认新消息不唤醒，手动恢复后能够继续。
5. 分别测试两个群合并执行、电脑离线、暂停后快速恢复，以及 A 工作区前台收到 B 的消息。

本地验证使用独立可丢弃 PostgreSQL/Redis。集成测试会清空数据，必须指向专用测试库，
不能使用云端或局域网试用库。本轮没有替用户执行云部署、升级运行中的 daemon 或生成安装包。
