## 本轮性能与交互修改

1. 登录/首次配置阶段不再同时加载 PC、移动端、管理端和引导界面；登录后仅加载所需平台。
2. 三处文档编辑器入口按需加载协作编辑器，聊天和登录不提前解析 TipTap/Yjs 编辑器代码。
3. PC 和移动端主聊天使用独立的会话选择器缓存；其他群的流式片段不再使当前聊天重绘。
   当前群更新、历史分页、最终消息去重和工作区切换保持原有语义。
4. Convene 双端可用状态统一，清除误启动路径；新增中文占位与手机返回处理。

### 构建对比

同机、同构建配置，独立输出目录，不覆盖本地试用服务的 `dist/`。
以下统计为 JavaScript 文件 gzip 体积，入口包含静态依赖闭包；不含 CSS、字体、图片、
接口数据以及用户主动打开的额外功能。缓存、HTTP 请求数和设备性能仍会影响真实启动耗时。

| 路径 | 优化前 | 优化后（约） |
| --- | ---: | ---: |
| 初始入口 | 755 KB | 270 KB，减少 64.3% |
| PC 聊天所需代码（含入口） | 755 KB | 529 KB |
| 手机聊天所需代码（含入口） | 755 KB | 491 KB |
| 文档编辑器 | 混在入口 | 仅打开文档时加载，额外约 183 KB |

### 渲染与交互验证

隔离浏览器夹具加载当前组件及 `dbf8b8c` 基线组件，使用 25 条历史消息和一个当前群
生成中的回复。首次挂载稳定后，向其他群注入 200 次流式更新：

| 被测组件树 | 基线 React 提交次数 | 优化后 |
| --- | ---: | ---: |
| PC 主聊天 | 400 | 0 |
| 移动主聊天 | 401 | 0 |

这些数字是开发模式 Profiler 的合成场景结果，不是手机帧率、耗电或生产 CPU 降幅。
当前群新增片段仍能显示。手机两个 Convene 入口均显示即将推出，启动 API 调用数为 0；
返回后保留草稿；模拟 Android 硬件返回回到聊天，没有触发退出。
延迟编辑器的加载态和文档不存在状态均已验证，未连接真实协作会话。

### 验证与交付边界

- 本轮聊天、草稿、附件、Android 返回相关 40 项测试通过。
- 上游已覆盖能力的附件缓存、项目记忆及多附件相关 36 项既有测试通过。
- 引擎重新发现 12 项测试通过；其 mock 测试使用进程级占位环境，不连接真实数据库。
- 前端类型检查、lint 和独立生产构建通过。
- 真实 PC 安装版和 Android 真机的长历史、输入法/软键盘、弱网、后台切前台、锁屏推送仍需验收。
- 第一批前端优化不涉及数据库；第二批新增会话暂停迁移及通知语义，见下文。没有云服务部署、安装包或公开发布。

## 第二批：执行控制与跨工作区通知

用户确认暂停只对当前会话生效，并持续到手动恢复。实现及升级边界见
[会话暂停与跨工作区通知](./CONVERSATION_CONTROLS.md)。

新增行为验证覆盖暂停持久化、两个收件箱入口、旧执行回复隔离、真实行锁竞态、旧分配确认失效、
共享群执行中断后其余群重跑、模型并发队列取消，以及工作区租约、静音和成员权限。
浏览器夹具仅使用合成数据，验证 PC/手机的请求与确认状态、恢复、跨工作区提醒和点击跳转，
未向用户真实群发消息或调用模型。

Linux 独立容器中的 runtime 集成测试 34 项全部通过，包含 Windows 因符号链接权限不能执行的路径。
最终定向单元回归 102 项通过，控制链路另做 15 项复验；Windows 上使用假模型 CLI 启动真实进程和工具子进程，取消后均已退出。
最终服务端集成复验 17 项通过（其中 7 项为本批业务场景），另有既有推送回归 7 项通过。
前后端类型检查、lint、独立前端生产构建、daemon 独立打包及 Electron 主进程/预加载语法检查通过。

额外全量测试没有得到全绿结果：Windows 的 PowerShell 5.1 路径、Codex 批处理假引擎和 POSIX 文件权限
共 4 项失败，已在未修改的 `dbf8b8c` 快照复现；全量单元测试还因既有 Redis 连接未退出而中止。
补齐 `procps` 和 `bubblewrap` 的 Docker 引擎夹具中，30 项通过、10 项失败、2 项跳过；
4 项真实子进程取消/正常退出测试通过，10 项 Codex 持久连接夹具失败也已在未修改基线复现。
这些失败和跳过不能计作通过，不能据此宣称所有沙箱、引擎和故障恢复场景均已验收。
本轮没有扩大为这些既有夹具和运行环境问题的修复。

自审另修复了初始控制读取暂时返回 503 时 daemon 可能停留在半启动状态的问题；
现在先启动重试通路，取得新鲜控制状态前不进入初筛或模型执行。启动故障及自动恢复的回归测试通过。

后续只读 CR 确认的三处竞态已修复：等待 token 的旧 IPC 固定执行版本并随暂停取消，
排队文件在下一轮前清理；已暂停会话的迟到 steering 不影响其他群；工作区首次租约改在收到
认证 `hello` 后上报，重连同样即时上报。旧协议文件清理失败时阻止重启，避免静默重放。
对应定向回归 15 项通过；扩展回归 82 项通过、4 项跳过。
跳过项包含本机缺少 PowerShell 5.1 PATH 的既有夹具，不计入通过数。

下一步真机验收继续覆盖长历史滚动、软键盘、弱网、后台切前台及锁屏推送，并对 Linux 多进程恢复
单独做故障压测；上面的合成渲染和包体数据不能替代这些设备结果。
